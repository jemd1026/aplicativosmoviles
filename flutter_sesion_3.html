1 Preparar el proyecto para consumir una API

35 minutos · dependencia, endpoint y estructura mental

Para consumir una API desde Flutter, primero hay que instalar un paquete que haga peticiones HTTP. En esta sesion se usara http, que es una de las opciones mas comunes para empezar. Como ya existe una API propia en D:\laragon\www\api_ucv, la guia puede trabajar directamente sobre ese backend.

⚠

Antes de correr cualquier ejemplo de esta sesion: agreguen la dependencia en pubspec.yaml y luego ejecuten flutter pub get. Si no hacen ese paso, Flutter mostrara errores de paquete no encontrado.

pubspec.yaml 
dependencies:
            flutter:
              sdk: flutter
            http: ^1.2.2
terminal 
flutter pub get

Qué es una API REST: es un servicio al que la app le pide datos usando una URL. La API responde casi siempre en formato JSON.

Qué significa GET: es la petición para leer datos, por ejemplo obtener una lista de productos o usuarios.

Qué es un endpoint: es la URL concreta que responde con cierto recurso, por ejemplo una lista de posts.

Regla didáctica: primero entiendan el flujo pedir datos → recibir JSON → convertir a objetos → mostrar en pantalla. Luego ya pueden agregar creación, edición o borrado.

Etapa Qué pasa Ejemplo
Request La app pide datos a una URL http.get(uri)
Response La API responde con JSON response.body
Parse Se convierte el JSON en objetos Dart fromJson
Render La app dibuja esos datos en widgets ListView.builder

API detectada para esta sesion: el proyecto expone el recurso usuarios con rutas limpias gracias al router de index.php y su .htaccess.

Campos que devuelve: id, nombre, apellido, email, telefono, activo, created_at. La contraseña no viaja al cliente, lo cual está correcto.

URL en Windows desktop o navegador: http://localhost/api_ucv/usuarios

URL en emulador Android: http://10.0.2.2/api_ucv/usuarios

URL en celular físico: usar la IP de la PC en la red local, por ejemplo http://192.168.1.10/api_ucv/usuarios

Método Ruta Uso en clase
GET /api_ucv/usuarios Listar usuarios
GET /api_ucv/usuarios/5 Ver detalle de un usuario
POST /api_ucv/usuarios Registrar usuario
PUT /api_ucv/usuarios/5 Actualizar usuario
DELETE /api_ucv/usuarios/5 Eliminar usuario

2 GET, fromJson y lista remota

65 minutos · primer consumo real desde internet

En lugar de una API pública de prueba, aquí conviene usar la API propia del curso. Así los ejemplos ya quedan alineados con el backend que también puede usarse desde Android Studio. El flujo será el mismo: consumir /api_ucv/usuarios, convertir el JSON en objetos Dart y mostrarlo en una lista.

lib/main.dart - ejemplo completo con api_ucv 
import 'dart:convert'; // permite convertir texto JSON a estructuras Dart
            import 'package:flutter/material.dart'; // widgets visuales
            import 'package:http/http.dart' as http; // paquete para peticiones HTTP

            void main() { // punto de entrada
            runApp(MiApp()); // arranca la aplicación
            }

            class MiApp extends StatelessWidget {
            @override
            Widget build(BuildContext context) {
            return MaterialApp(
            debugShowCheckedModeBanner: false,
            theme: ThemeData(useMaterial3: true),
            home: UsuariosPage(),
            );
            }
            }

            class Usuario { // modelo para representar cada fila recibida de la API
            final int id;
            final String nombre;
            final String apellido;
            final String email;
            final String telefono;
            final int activo;

            Usuario({
            required this.id,
            required this.nombre,
            required this.apellido,
            required this.email,
            required this.telefono,
            required this.activo,
            });

            factory Usuario.fromJson(Map<String, dynamic> json) { // mapea JSON a objeto Dart
            return Usuario(
            id: json['id'],
            nombre: json['nombre'] ?? '',
            apellido: json['apellido'] ?? '',
            email: json['email'] ?? '',
            telefono: json['telefono'] ?? '',
            activo: json['activo'] ?? 0,
            );
            }
            }

            Future<List<Usuario>> obtenerUsuarios() async { // solicita la lista a la API
            final uri = Uri.parse('http://10.0.2.2/api_ucv/usuarios'); // emulador Android
            // Si ejecutan en Chrome o Windows desktop, usar: http://localhost/api_ucv/usuarios
            final response = await http.get(uri); // hace la petición GET

            if (response.statusCode == 200) {
            final List data = json.decode(response.body); // convierte el texto JSON en lista
            return data.map((item) => Usuario.fromJson(item)).toList(); // convierte toda la lista JSON
            } else {
            throw Exception('Error al cargar usuarios');
            }
            }

            class UsuariosPage extends StatelessWidget { // pantalla que consume y muestra la API
            @override
            Widget build(BuildContext context) {
            return Scaffold(
            appBar: AppBar(title: Text('Usuarios remotos')),
            body: FutureBuilder<List<Usuario>>( // escucha el resultado de la petición
            future: obtenerUsuarios(),
            builder: (context, snapshot) {
            if (snapshot.connectionState == ConnectionState.waiting) {
            return Center(child: CircularProgressIndicator()); // loading
            }

            if (snapshot.hasError) {
            return Center(child: Text('Error: ${snapshot.error}')); // error
            }

            final usuarios = snapshot.data ?? []; // usa lista vacía si aún no hay data

            return ListView.builder(
            itemCount: usuarios.length, // total de usuarios a pintar
            itemBuilder: (context, index) {
            final usuario = usuarios[index]; // usuario actual
            return Card(
            margin: EdgeInsets.symmetric(horizontal: 12, vertical: 6),
            child: ListTile(
            leading: CircleAvatar(child: Text(usuario.id.toString())),
            title: Text('${usuario.nombre} ${usuario.apellido}'),
            subtitle: Text(
            usuario.email,
            maxLines: 1,
            overflow: TextOverflow.ellipsis,
            ),
            trailing: Icon(
            usuario.activo == 1 ? Icons.check_circle : Icons.cancel,
            color: usuario.activo == 1 ? Colors.green : Colors.red,
            ),
            ),
            );
            },
            );
            },
            ),
            );
            }
            }
💡

Qué enseña este ejemplo: instalar http, consumir una API real del curso, convertir JSON a objetos con fromJson y mostrar estados de loading, error y data con FutureBuilder.

3 Estados visuales, refresh y detalle

55 minutos · no solo cargar datos, tambien manejar experiencia real

Cuando una app ya consume una API, no basta con mostrar la lista cuando todo sale bien. Tambien hay que pensar qué mostrar mientras carga, qué hacer si falla, cómo actualizar manualmente y cómo pasar a una pantalla de detalle. En este caso, el detalle puede mostrar nombre completo, correo, teléfono y estado del usuario.

Loading se representa con un CircularProgressIndicator.

Error se representa con un mensaje visible y, si hace falta, un botón para reintentar.

Data es el estado correcto: la lista ya llegó y puede mostrarse.

Refresh permite pedir la información otra vez, por ejemplo con RefreshIndicator.

Detalle permite tocar un item y abrir otra pantalla con toda su información.

Lista de usuarios con refresh y detalle 
class _UsuariosPageState extends State<UsuariosPage> { // versión con estado para poder refrescar
            late Future<List<Usuario>> futureUsuarios; // guarda la petición actual

            @override
            void initState() {
            super.initState();
            futureUsuarios = obtenerUsuarios(); // lanza la primera carga al abrir la pantalla
            }

            Future<void> recargar() async { // vuelve a pedir datos manualmente
            setState(() {
            futureUsuarios = obtenerUsuarios();
            });
            }

            @override
            Widget build(BuildContext context) {
            return Scaffold(
            appBar: AppBar(title: Text('Usuarios con refresh')),
            body: FutureBuilder<List<Usuario>>(
            future: futureUsuarios,
            builder: (context, snapshot) {
            if (snapshot.connectionState == ConnectionState.waiting) {
            return Center(child: CircularProgressIndicator());
            }
            if (snapshot.hasError) {
            return Center(
            child: Column(
            mainAxisAlignment: MainAxisAlignment.center,
            children: [
            Text('Error al cargar usuarios'),
            SizedBox(height: 12),
            ElevatedButton(
            onPressed: recargar,
            child: Text('Reintentar'),
            ),
            ],
            ),
            );
            }

            final usuarios = snapshot.data ?? [];

            return RefreshIndicator( // habilita arrastrar para refrescar
            onRefresh: recargar,
            child: ListView.builder(
            itemCount: usuarios.length,
            itemBuilder: (context, index) {
            final usuario = usuarios[index];
            return ListTile(
            title: Text('${usuario.nombre} ${usuario.apellido}'),
            subtitle: Text(usuario.email),
            onTap: () { // abre una pantalla con más información del usuario
            Navigator.push(
            context,
            MaterialPageRoute(
            builder: (context) => UsuarioDetailPage(usuario: usuario),
            ),
            );
            },
            );
            },
            ),
            );
            },
            ),
            );
            }
            }

4 Separar model, service y pages

45 minutos · organizar para no dejar todo en main.dart

Una vez que aparece la API, el archivo main.dart no debería seguir creciendo indefinidamente. Conviene separar los modelos, el acceso a red y las pantallas. Como esta sesión ya trabaja con api_ucv, abajo queda la estructura aplicada al recurso usuarios.

Estructura sugerida 
lib/
            main.dart
            models/
              usuario.dart
            services/
              api_service.dart
            pages/
              usuarios_page.dart
              usuario_detail_page.dart
lib/services/api_service.dart 
import 'dart:convert'; // parseo de JSON
            import 'package:http/http.dart' as http; // cliente HTTP
            import 'package:flutter/foundation.dart'; // debugPrint
            import '../models/usuario.dart';

            class ApiService { // concentra la comunicación con el backend
            Future<List<Usuario>> obtenerUsuarios() async {
            debugPrint('[API] Iniciando petición GET de usuarios');
            final uri = Uri.parse('http://10.0.2.2/api_ucv/usuarios'); // URL para emulador Android
            final response = await http.get(uri); // llamada GET al backend
            debugPrint('[API] statusCode: ${response.statusCode}');

            if (response.statusCode == 200) {
            final List data = json.decode(response.body);
            debugPrint('[API] usuarios recibidos: ${data.length}');
            return data.map((item) => Usuario.fromJson(item)).toList();
            } else {
            debugPrint('[API] Error al cargar datos');
            throw Exception('Error al cargar datos');
            }
            }
            }

lib/pages/usuarios_page.dart 
import 'package:flutter/foundation.dart'; // utilidades como debugPrint
            import 'package:flutter/material.dart'; // interfaz
            import '../models/usuario.dart';
            import '../pages/usuario_detail_page.dart';
            import '../services/api_service.dart';

            class UsuariosPage extends StatefulWidget { // necesita estado por la carga remota
            const UsuariosPage({super.key});

            @override
            State<UsuariosPage> createState() => _UsuariosPageState();
            }

            class _UsuariosPageState extends State<UsuariosPage> {
            final apiService = ApiService(); // service encargado de hablar con la API
            late Future<List<Usuario>> futureUsuarios; // petición en curso

            @override
            void initState() {
            super.initState();
            debugPrint('[UI] initState de UsuariosPage');
            futureUsuarios = apiService.obtenerUsuarios(); // dispara la carga inicial
            }

            Future<void> recargar() async {
            debugPrint('[UI] recargando lista');
            setState(() {
            futureUsuarios = apiService.obtenerUsuarios(); // crea una nueva petición para refrescar
            });
            }

            @override
            Widget build(BuildContext context) {
            debugPrint('[UI] build de UsuariosPage');
            return Scaffold(
            appBar: AppBar(
            title: Text('Usuarios remotos'),
            ),
            body: FutureBuilder<List<Usuario>>( // reacciona según el estado del Future
            future: futureUsuarios,
            builder: (context, snapshot) {
            if (snapshot.connectionState == ConnectionState.waiting) {
            return Center(
            child: CircularProgressIndicator(),
            );
            }

            if (snapshot.hasError) {
            return Center(
            child: Column(
            mainAxisAlignment: MainAxisAlignment.center,
            children: [
            Text('No se pudo cargar la API de usuarios'),
            SizedBox(height: 12),
            ElevatedButton(
            onPressed: recargar,
            child: Text('Reintentar'),
            ),
            ],
            ),
            );
            }

            final usuarios = snapshot.data ?? []; // evita null si la data todavía no existe

            return RefreshIndicator(
            onRefresh: recargar, // función que se ejecuta al arrastrar
            child: ListView.builder(
            itemCount: usuarios.length,
            itemBuilder: (context, index) {
            final usuario = usuarios[index];
            return Card(
            margin: EdgeInsets.symmetric(horizontal: 12, vertical: 6),
            child: ListTile(
            leading: CircleAvatar(child: Text(usuario.id.toString())),
            title: Text('${usuario.nombre} ${usuario.apellido}'),
            subtitle: Text(
            usuario.email,
            maxLines: 1,
            overflow: TextOverflow.ellipsis,
            ),
            onTap: () {
            debugPrint('[UI] abrir detalle del usuario ${usuario.id}'); // log útil para seguir el flujo
            Navigator.push(
            context,
            MaterialPageRoute(
            builder: (context) => UsuarioDetailPage(usuario: usuario),
            ),
            );
            },
            ),
            );
            },
            ),
            );
            },
            ),
            );
            }
            }

Regla práctica: el modelo define la forma de los datos, el service habla con la API y la page se concentra en mostrar la interfaz. Además, los debugPrint() ayudan a seguir el flujo en terminal mientras cargan, refrescan o abren detalle. Esta misma estructura luego puede ampliarse para POST, PUT y DELETE.
